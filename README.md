# 1UOSAUTO 发布与更新清单

这个仓库只做两件事：

1. 放 **`update.json`** —— 程序「关于」页的「检查更新」读的就是它
2. 放 **Releases** —— 安装包发在这里

**源码不在这里。** 这个仓库是公开的，只是因为更新检查必须能匿名读到清单：
私有仓库的 raw 内容和 Release 资产都要 token，而 token 打进客户端等于公开它，
任何人反编译一下就能拿去读私有仓库。公开仓库不等于开源。

## update.json

```json
{
  "version": "0.0.2",
  "notes": "修复了 XXX；新增 YYY。",
  "download_url": "https://github.com/HikAr131/1UOSAUTO-release/releases/latest",
  "published": "2026-09-10"
}
```

只有 `version` 是必需的，其余三个缺省为空字符串。

- `version` 三段式，解析很宽容（`0.0.2` / `v0.0.2` / `0.2` / `0.2.0-beta` 都认），
  比较是**逐段按数字**比的，所以 `1.10.0` 大于 `1.9.0`
- `notes` 一两句话，直接显示在「关于」页的状态行里，别写长篇
- `download_url` 留空的话按钮不会变成「去下载」，只会提示手动去发布页
- `published` 目前纯记录，界面没用上

## 发版时

清单里的 `version` 必须**严格大于**程序自身的版本，用户才会看到提示。
两边写反了不会报错，只是没人收到更新。

程序自身的版本在产品仓库的 `正常系统端/build.rs`（`DISPLAY_VERSION`）。发版时两处一起改。

## 程序不会自己更新自己

「检查更新」最多把人送到下载页，程序不会替换自己的 exe。Windows 上程序覆盖不了
正在运行的自己，绕过去的那些写法一旦出错就把用户的 exe 弄没了——而用这个工具的人
往往正准备重装系统，手边未必有第二台机器。
